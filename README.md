# Мост Telegram ↔ MAX

[Скачать Windows EXE](https://github.com/XPprojects-inc/telegram-max-bridge/releases/latest) · [Релизы](https://github.com/XPprojects-inc/telegram-max-bridge/releases)

Программа копирует новые сообщения между группами Telegram и MAX. Версия 3.1 с окном настройки поддерживает несколько независимых пар: Telegram A ↔ MAX A, Telegram B ↔ MAX B и далее. Каждая группа входит только в одну пару. В Telegram работает бот, в MAX — ваш обычный аккаунт. Создавать MAX-бота не требуется. Сообщения содержат подпись с платформой и именем автора.

**Состояние поставки:** готов самостоятельный `TelegramMaxBridge.exe` для Windows 10/11 x64. Python, библиотеки и MAX на ПК устанавливать не нужно; установленный Telegram Desktop также не является технической зависимостью. 66 автоматических тестов пройдены. Реальный обмен с MAX ещё не проверен: необходимы вход владельца аккаунта и выбор групп.

## Запуск одним EXE — рекомендуемый способ

Новая поставка называется `TelegramMaxBridge-v3.1.exe`. Перед запуском закройте старый `TelegramMaxBridge.exe`; сохранённые настройки и связки используются из того же профиля. В командах ниже имя `TelegramMaxBridge.exe` обозначает исполняемый файл вашей версии (сборка из исходников использует имя без суффикса).

1. Запустите `TelegramMaxBridge.exe` обычным двойным щелчком.
2. Введите токен бота и нажмите **Подключить Telegram**. Токен не встроен в EXE; после проверки он сохраняется через Windows DPAPI и привязан к вашему пользователю Windows.
3. Добавьте бота администратором в каждую нужную Telegram-группу. Отправьте `/bridge` в каждой и нажмите **Обновить группы Telegram**.
4. Нажмите **Войти / обновить MAX**. Отсканируйте QR-код в MAX на телефоне. При двухэтапной проверке приложение покажет отдельное поле пароля. Аккаунт уже должен состоять в нужных MAX-группах.
5. Выберите группу Telegram и группу MAX, нажмите **Добавить связку**. Повторите для остальных пар.
6. Нажмите **Запустить мост**. Окно можно свернуть. Закрытие окна или выключение компьютера останавливает копирование.

Добавление бота в несколько групп само по себе не связывает их: пары выбираются явно. Одна группа не может одновременно входить в две связки; рассылка одной группы сразу в несколько в этой версии не предусмотрена. Все MAX-группы должны быть доступны одному подключённому аккаунту MAX, все Telegram-группы — одному боту.

Для изменения связок сначала нажмите **Остановить**. При удалении пары её неотправленные задания отменяются. Кнопка **Очередь и ошибки** показывает состояние и позволяет повторить неопределённую отправку после проверки целевой группы.

Один EXE содержит код и зависимости, но при работе создаёт настройки, очередь и сессию в `%LOCALAPPDATA%\TelegramMaxBridge`. QR отображается прямо в окне и не сохраняется как файл. Настройки графической версии независимы от старых консольных запускателей. Не переносите папку сессии другим людям.

Встроенная проверка без сети: `TelegramMaxBridge.exe --self-test report.json`. Она проверяет Tk/Tcl, QR/Pillow, Windows DPAPI, TLS, создание WebClient MAX и маршрутизацию двух пар. Сборка проверена на Windows 11 x64; отдельная чистая Windows 10 VM не использовалась.

## Старый консольный запуск из исходников (одна пара через мастер)

1. Добавьте своего бота в нужную группу Telegram. Назначьте администратором, чтобы он получал все сообщения. Возможность отправлять сообщения и файлы должна быть разрешена.
2. Отправьте `/bridge` в этой группе. Бот не отвечает на эту команду: она нужна локальному мастеру, чтобы обнаружить группу.
3. Откройте **SETUP.cmd**. Сначала установите Python и запустите INSTALL.cmd. Нажмите Enter, когда мастер попросит, и выберите номер группы Telegram.
4. На компьютере откроется QR-код. В MAX на телефоне откройте раздел устройств и отсканируйте его для входа. Коды и пароль вводите только локально; в переписку с ассистентом их не отправляйте.
5. Выберите номер группы MAX из списка. Ваш аккаунт уже должен состоять в этой группе и иметь возможность писать в неё.
6. Откройте **START.cmd**. Оставьте окно открытым, а компьютер — включённым. Остановка: `Ctrl+C`.
7. Проверьте группу: отправьте по одному текстовому сообщению и фото с каждой стороны. Сообщения MAX можно отправить с того же аккаунта, которым выполнен вход.

QR-код и сессия находятся локально в `data/`. После завершения настройки изображение QR удаляется. Следующие запуски используют сохранённую сессию. Если MAX отзовёт сессию, потребуется новый вход.

## Перенос на другой компьютер

Распакуйте архив в отдельную папку. Установите Python 3.10 или новее, запустите INSTALL.cmd, затем SETUP.cmd и START.cmd. В архив **не включены** токен, сессия MAX, настройки групп, база сообщений и виртуальное окружение. Мастер запросит Telegram-токен скрытым вводом; можно также задать переменную окружения `TELEGRAM_BOT_TOKEN`.

Для Linux/macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python bridge.py setup
.venv/bin/python bridge.py run
```

Одновременно запускайте только один экземпляр моста с этим Telegram-токеном. Для постоянной работы нужен постоянно включённый компьютер или сервер. Автозапуск в Windows этой поставкой не устанавливается.

## Что передаётся

| Тип | Поведение |
| --- | --- |
| Текст и подписи | Обычный текст с именем автора; длинный текст разбивается |
| Фото и видео | Отправляются вложениями, подпись автора отдельная |
| Документы и аудиофайлы | Передаются файлами |
| Голосовые Telegram → MAX | OGG-файл; запись не перекодируется |
| Голосовые MAX → Telegram | Голосовое вложение, если MAX предоставил URL |
| Стикеры | Файл; анимированные стикеры могут не иметь предпросмотра |
| Опросы в обе стороны | Создаётся самостоятельный опрос с теми же вариантами; результаты другой платформы — отдельной сводкой |
| Ответы | Связанный ответ на соответствующую копию или оригинал, если они зарегистрированы мостом |
| Изменения текста и подписей | Обновляется текст копии; замена самого вложения не передаётся |
| Реакции | Обновляемая сводка «Реакции Telegram: …» или «Реакции MAX: …» ответом на сообщение |
| Закрепления | Передаётся новое текущее закрепление известного мосту сообщения; нужны права закрепления |
| Удаления MAX → Telegram | Удаляются копии исходного MAX-сообщения, если Telegram разрешает удаление |
| Местоположение и контакт Telegram → MAX | Текстовое представление |
| Неподдерживаемое/недоступное вложение | Отметка о невозможности переноса |

Лимит каждого переносимого вложения — **20 МиБ**. Он также применяется при потоковом скачивании. Фотоальбомы переносятся отдельными изображениями по порядку, без объединения в нативный альбом. Подпись передаётся отдельным текстом. Изображения, присланные как документы, остаются файлами. Фото больше 10 МиБ (до общего лимита 20 МиБ), а также фото с явно отклонённым Telegram форматом передаются исходным файлом. При сетевом сбое скачивания вложение остаётся в очереди для повторной попытки; неопределённый результат отправки автоматически не повторяется. Форматирование и темы форумов не переносятся. Telegram Bot API не сообщает об обычных удалениях сообщений: направление удаления Telegram → MAX недоступно. Снятие закрепления и весь список закреплённых сообщений не синхронизируются. Голосование закрывается только на исходной стороне; в удалённой сводке появляется отметка о закрытии.

### Опросы и сводки

Голоса на двух платформах независимы. Удалённая статистика показывается рядом с опросом, например: «Голоса Telegram: 1. Да — 5; 2. Нет — 2». Обновляется одна сводка, а не публикуется новая при каждом голосе. Имена голосующих не переносятся. Скрытые результаты MAX отображаются как «скрыто».

**Создавайте опрос в Telegram обычным способом.** Мост ответит новым опросом от бота с тем же вопросом и вариантами и свяжет его с MAX. Рядом появится пояснение, что голосовать нужно в копии от бота. Исходный опрос остаётся; его уже поданные голоса не переносятся. Это необходимо, поскольку Telegram не сообщает боту живые результаты обычных чужих опросов.

При сбое после создания копии мост сохраняет её ID и использует при ручном повторе, не создавая её заново. Неопределённый результат самой отправки всё равно требует проверки в очереди. Опросы, обработанные старыми версиями, автоматически не пересоздаются. Ответы на исходный опрос в Telegram связываются с опросом MAX; ответы из MAX направляются к опросу от бота.

Команда администратора `/bridge_poll Вопрос | Ответ 1 | Ответ 2` также работает и позволяет сразу создать опрос от бота. Копии анонимные; режим нескольких вариантов сохраняется. Удалённые голоса отображаются сводкой, голоса на платформах независимы.

Опросы MAX проверяются примерно каждые 30 секунд; задержка растёт при большом количестве опросов. Изменение вопроса/вариантов существующего опроса, специальные режимы викторины и новые возможности Telegram-опросов не гарантируются.

Реакции передаются количеством, без действий от имени участников. Счётчик Telegram строится по полученным событиям; пропущенные события и реакции до подключения восстановить полностью нельзя. Пользовательские emoji могут отображаться идентификатором. Для реакций бот должен быть администратором.

Связи оригиналов и копий сохраняются для сообщений, обработанных версией 3.0. Для старых копий версии 2 они не восстанавливаются. Ответ на неизвестное старое сообщение отправляется без связанного ответа. Правки относятся к тексту исходного сообщения; ручная правка или удаление его копии не изменяет чужой оригинал. При сокращении длинного текста лишняя часть помечается «Продолжение удалено».

## Как исключаются повторы

- Для Telegram проверяется ID самого бота.
- Для MAX до отправки сохраняются клиентский ID сообщения и хеш точного текста; после ответа сервера — ID сообщения MAX. Эхо подавляется только для аккаунта моста. Ваши обычные сообщения с этого аккаунта копируются.
- Если вы вручную отправите от своего MAX-аккаунта **в точности такой же текст, как ранее отправлял мост**, он тоже будет признан эхом. Обычно тексты моста отличаются служебной подписью `Telegram · Имя`.
- ID обработанных входящих сообщений и очередь хранятся в SQLite. Повторная доставка одного события не создаёт новую задачу.
- Части сообщения и подготовленные вложения сохраняются до отправки. После успешной передачи временные вложения и содержимое задания удаляются. Для правок и сводок версия 3 хранит в SQLite снимки исходных сообщений, связи с копиями, счётчики и текст сводок. Это локальная база переписки; удаление связки удаляет её записи синхронизации.
- При неопределённом исходе отправки (например, обрыве соединения после запроса) задача получает статус `uncertain`. Автоматического повтора нет: так исключается слепая повторная отправка. Это означает, что при некоторых сбоях потребуется ручная проверка.

## Сбои и диагностика

STATUS.cmd показывает количество задач и ID задач, требующих проверки. Его можно открыть во время работы моста. Сообщения об ошибках также видны в окне START.cmd. Тексты сообщений и токены в диагностический вывод не записываются.

В графической версии используйте «Очередь и ошибки»: задания с ID `S…` относятся к правкам, сводкам, закреплениям и созданию опросов. Перед ручным повтором проверьте целевую группу: при потере ответа сервера сообщение могло уже появиться. Консольные STATUS/retry обслуживают только основную очередь копирования; для заданий `S…` используйте графическую версию.

Если задача `uncertain` действительно не дошла, остановите мост, откройте терминал в папке программы и выполните:

```powershell
.venv\Scripts\python.exe bridge.py retry 12
```

Замените `12` на ID задания из STATUS.cmd. Подтвердите повтор локально словом `RETRY`, затем снова запустите START.cmd. Уже подтверждённые части пропускаются; часть с неопределённым результатом может продублироваться, если она всё-таки дошла.

При временной недоступности Telegram опрос возобновляется с сохранённого offset. Telegram хранит необработанные обновления не более 24 часов. История MAX проверяется каждые 30 секунд только для выбранной группы, начиная со времени связывания. Доступность всей истории зависит от MAX; гарантии восстановления после любого срока простоя нет. Ограничение одного прохода — 50 000 сообщений. При превышении или ошибке в консоли появляется предупреждение.

Новые сообщения Telegram и MAX, появившиеся до первого связывания, не копируются. При выборе другой пары групп старые незавершённые задачи отменяются, чтобы содержимое прежней группы не попало в новую.

Если список Telegram пуст, снова отправьте `/bridge` и повторите SETUP.cmd. Если группы MAX нет в списке, проверьте участие аккаунта и повторите вход/настройку. Если Telegram выдаёт 409, остановите другой процесс, использующий токен. Программа не удаляет существующий webhook автоматически. Если Telegram преобразовал группу в супергруппу, повторите настройку, выбрав её новый ID.

## Аккаунт и секреты

MAX подключён через [неофициальную библиотеку PyMax](https://github.com/MaxApiTeam/PyMax), а не официальный Bot API. Авторы библиотеки предупреждают об изменениях внутреннего API без уведомления и возможной блокировке аккаунта. Сообщения из Telegram публикуются от имени подключённого MAX-аккаунта.

Локальные `token.txt` и `data/max-session.db` дают доступ к боту и сессии MAX. Не публикуйте их и не пересылайте всю рабочую папку. Для передачи исходников используйте архив без секретов. При утечке токена перевыпустите его через BotFather и замените в настройках.

## Проверки и зависимости

```powershell
.venv\Scripts\python.exe -m unittest -v
.venv\Scripts\python.exe bridge.py check
```

66 локальных тестов проверяют маршрутизацию, изоляцию пар, эхо, перезапуск, очередь, историю MAX, UTF-16-лимит, вложения, ответы в обе стороны, правки, удаления, реакции, опросы, права администратора, закрепления и события, приходящие до копирования. Тесты используют подменённые сетевые ответы; они не подтверждают совместимость с живым MAX-аккаунтом.

Исходный GUI: `desktop.py`; сетевой контроллер: `controller.py`; движок: `bridge.py`; правки и сводки: `sync_engine.py`. Сборка EXE — `BUILD.ps1` (PyInstaller 6.22.3). Сведения о лицензиях включены в `THIRD_PARTY_NOTICES.txt` и внутрь EXE.

Версия PyMax закреплена на коммите `53103f0c8df32f36110cbe0bcbfc3ad82173808a` (2.4.1). Адаптер использует внутренний метод загрузки файлов и модели отправки этой версии, чтобы сохранять буквальный текст и задавать клиентский ID до отправки. Обновлять библиотеку следует только после проверки адаптера.
